# ADR 0007: Separate Discovery graph and shared assignment recovery subgraph

Status: accepted (2026-11-23). Normative specification: [#246](https://github.com/Cruel/noveltea-gen/issues/246). Implementation: [#247–#260](https://github.com/Cruel/noveltea-gen/issues/247).

## Context

Baseline Story Discovery currently runs in an independent Studio/Pi session state machine before a Git-backed Generation Job exists. Its correction policy, persistence and Review loops differ from the Generation graph's established `assess_recovery` / `RecoveryLifecycle` contract. Fixing one defect in the current Discovery flow cannot guarantee the original writer and reviewer sessions will survive another defect, crash or interruption. Meanwhile, Generation has multiple specialist-local correction loops whose recovery authority should be consolidated without replacing the source and effect receipts established by #238–#245.

A single earlier-started Generation graph would conflate unapproved author conversation with canonical Job/Git authority. Preserving the standalone non-graph Discovery state machine would preserve a second orchestration and restart policy. Both are undesirable.

## Decision

**Separate execution graphs, one author-facing Story Chat.** Discovery gets a separately checkpointed LangGraph owned by the Studio Story/Chat/first Turn and backed by Studio's supported persistence engines. It does not create a Generation Job, Story commit, writer grant or fabricated Generation recovery case before author approval. On exact approved Creative Direction, an authenticated, idempotent handoff creates or resumes the original Generation Job. Both execution graphs reuse the existing structured Author Question/Question Set schema and Chat interface; submitted answers remain the authoritative author evidence.

**One reusable assignment lifecycle.** After a parent graph authenticates a bounded specialist assignment, a shared checkpointed LangGraph subgraph begins *before* its first Pi invocation and controls the assignment's writer operation, native/source checks, required independent Review, substantive corrections and eventual result. Domain adapters implement the work and verification; global planning, Story-wide/multi-item Review, cross-owner scheduling, Work-plan/inventory reconciliation, safe author-update intake and final fulfillment remain parent responsibilities. Serialized composite work (such as World then Character or Choice then Puzzle) retains distinct source, review and commit boundaries. There is no second Story-wide scheduler.

**One recovery policy and original conversations.** Reuse and refactor the existing Generation recovery policy, `assess_recovery`, response-contract correction, original-effect reconciliation, Pi writer/reviewer receipts and ADR 0006 Review convergence. Trusted source/authorization adapters differ for Discovery and Generation, but a child does not hold a competing authoritative RecoveryLifecycle or invent new Generation Case IDs. A bounded, tool-free malformed-response correction or within-turn native validation can be performed locally; substantively new scope/owner/plan decisions, genuinely stalled work, unfamiliar strategies or ambiguous effects reach the shared assessor. An unchanged assignment keeps its original writer and independent reviewer Pi conversations. A changed assignment gets new authorized Review with sealed predecessor evidence.

**Distinguish interruption from logical suspension.** In pinned LangGraph.js 1.5.2, a genuinely interrupted nested task can resume via `Command(resume)`; a child that returns `needs-prerequisite` at `END` has no pending task to resume. Cross-owner support therefore proceeds by returning a sealed *logical assignment phase* to the parent; after verified support, the parent re-enters the same logical assignment with authenticated original Pi sessions, Review history, source lineage and invocation/effect receipts, **not** by calling `Command(resume)` against a completed child. The child must release its writer claim before supporting work. A graph checkpoint alone never proves that an external Pi call, file write or Git commit may be replayed.

**Typed outcomes preserve safe-stop distinctions.** The child reports `verified`, `needs-prerequisite`, `awaiting-author`, `paused`, `fenced` or `unresolved`. The last distinguishes independently corroborated exhaustion/nonconvergence or sealed diagnostic stop from an author/resource pause and a source-integrity fence. Parent cancellation is a separate terminal control, never a resumable pause. An outcome is not a grant or proof of Story-wide completion.

**Clean pre-release execution cutover for both phases.** Replace rather than dual-run the old authoritative onboarding session engine and the old executable Generation dispatch/checkpoint protocol. Incompatible beta Discovery or Generation executions are explicitly rejected/reset, **not migrated and not kept runnable via pre-cutover fallback**; the absence of an authenticated current-format Turn plan must never route production into an old Generation specialist path. Preserve unrelated canonical Story/Git data, read-only original Pi/Git/Review receipts for safe inspection, and trustworthy **current-format** Job/RecoveryCase continuity, but those preservation obligations do not confer legacy execution authority. Deterministic fixtures use the current lifecycle with isolated test identity rather than a historical production fallback. One cumulative original first-Turn resource envelope spans both phases with authenticated usage handoff.

## Consequences and verification

This decision refines [ADR 0002](0002-goal-driven-story-orchestration.md) without adding another Generation scheduler, preserves [ADR 0004](0004-shared-author-question-boundary.md) for author inputs, and follows the safety rules of [ADR 0005](0005-bounded-correction-and-recovery.md) as partially superseded by [ADR 0006](0006-persistent-review-and-incremental-story-blueprints.md). The normative existing Generation recovery contract remains authoritative and must be synchronized during migration, not bypassed.

First qualify an actual Generation assignment child, nested checkpoint namespaces, logical phase re-entry, original Pi/Git effect reconciliation, and current-plan/author-intake parent gates (#247). Discovery then migrates without waiting for every Generation specialist migration (#256–#258). Qualify persistent SQLite Generation checkpoints, Studio SQLite/PostgreSQL, original-session Review continuity, cross-specialist support, crash windows, source/tamper fences and final Story fulfillment before closing #260. The November 23 Luna Discovery run's consecutive source/provenance errors are a mandatory nonprivate regression under #257. The acceptance test must demonstrate verified correction and continuation, not merely a queued recovery decision.

**Pre-release compatibility invariant:** Do not add beta checkpoint schema migration readers, dual active execution paths or production compatibility selected by a missing Turn plan. During incremental specialist migration, current-contract assignments may temporarily use still-unmigrated domain adapters, but an obsolete *format* does not become a supported execution mode. Block closure of #247 if its Foundation child is conditional on a historical no-Turn fallback, and block final #260 certification until all such production fallbacks are retired. The approved functional spec is #246 and the implementation tickets are #247–#260; the design interview draft is not an additional technical authority.

## Non-negotiable boundary and authority

ADR [0002](adr/0002-goal-driven-story-orchestration.md): one goal-driven **production** graph and trusted controller; model proposals do not authorize writes. ADR [0005](adr/0005-bounded-correction-and-recovery.md) as **superseded in part** by [0006](adr/0006-persistent-review-and-incremental-story-blueprints.md): original Pi writer and persistent independent read-only reviewer conversations, semantic convergence and resources, no mandatory fresh reviewer per correction, no fixed 2/3/12 ordinary semantic attempt cutoff, no cross-review matching of creative issue identities. The historical v1 constants/author grants in [repair-ledger.ts](../src/repair-ledger.ts) remain readable **only for legacy provenance**. Separate bounded protocol response retries (two corrections after original, at most one authorized fresh invocation), infrastructure retries, integrity checks and job Pi budget ceilings still apply. Review disagreement, repeated nonprogress and oscillation require a distinct independent diagnosis/strategy, not automatic acceptance.

**Invariant:** Within an admitted autonomous generation Turn, a recoverable unresolved problem cannot become terminal **only** because no per-case handler was registered. First validate source/effects, author control, and existing deterministic correction/review/Repair routes. If a trustworthy semantic/plan failure remains unfamiliar, route it through one **actually started** bounded read-only diagnostic/correction agent and the controller's independently validated correction proposal before considering a recoverable stop. A speculative decision, completed *initial failed specialist*, queued invocation, protocol assessment, or model recommendation with no proven invocation is **not** an agent correction attempt. Attempts are corroborated by the existing Pi invocation/start receipt and settled response (for correction work: a completed submitted revision); multiple probes of the same immutable source cannot reset them. Untrusted source/provenance, protected author approval, cancellation, pending genuine Author Question, exhausted resources/provider, uncertain writer effects, and nonconverging correction may pause/fence without a dangerous model call. A pure read-only diagnostic never confers a write lease, overrules a sealed negative review or marks the Story complete.

The type-only future state contract is [generation-recovery-contract.ts](../src/generation-recovery-contract.ts). **C01 does not add a fourth active channel** or change dispatch today.

## Typed identity, decision and lifecycle

- **Case**: `RecoveryCase.schema = noveltea-generation-recovery-case/v1`; closed cause `semantic | protocol | infrastructure | authorization | resource | execution-control | integrity`; explicit `observation` (throw/returned negative/preflight/refused review/incomplete/reconciliation); `effect` (no effect, read-only, settled no-write, verified committed, *uncertain writer*). Immutable `origin`: job ID, original job Thread ID and actual LangGraph Thread ID, original Turn digest, pinned plan version, trusted HEAD (nullable only when unavailable), bound assignment, original operation and versioned failed check. `evidence[]` contains only store/ref/digest links to authentic existing receipts; `causedByCaseId` links but does not copy the ledger.
- **Case identity**: SHA-256 of a canonically serialized **ordered** tuple `(schema, jobId, jobThreadId, graphThreadId, turnDigest, planVersion, sourceHeadSha, assignmentId, operation, check, checkVersion, kind, observation, sorted unique evidence [store, ref, digest])`. Exclude error wording, model advice, wall clock, attempt count and graph cursor. The admission-time evidence set is frozen for the case identity; later invocation, review and correction receipts are linked by the decision/attempt and existing stores, **never appended to the identity tuple**. The same failure on the same sources deduplicates even across resume; a new verified source/change to a different failed check creates a distinct case. A missing/untrusted critical identity is a **fenced** case, never a fabricated HEAD or case key. Revalidate the claimed HEAD/check/source before any effect, including original blocked-Thread reentry.
- **Decision**: `RecoveryDecision.schema = noveltea-generation-recovery-decision/v1` with the exact case ID, checked HEAD and immutable evidence links. Its discriminated `action` is one of **known-correction**, **plan-amendment**, **diagnostic**, **reconcile-effects**, **continue-independent**, **pause**, **exhausted**, **integrity-fence**. Each has typed destination/required proof. `diagnostic.attemptRef` is null until an **actual** original model attempt starts; settled completion must be independently corroborated through the indexed `RecoveryAttempt` original invocation and Pi references. `plan-amendment` describes scope/owner but is **not** authorization. Only controller-granted, source-current specialist scopes and existing protection/approval gates can dispatch a writer.
- **Lifecycle**: `RecoveryLifecycle.schema = noveltea-generation-recovery/v1`, one active case, a stable pending queue of distinct cases, one decision, one original-invocation `RecoveryAttempt` reference (or null), phase `idle → assessing → reconciling | diagnosing | correcting → verifying → resolved → idle`, plus explicit `paused` or `fenced`. Persist a phase **before** an irreversible side effect and preserve links to the original started/settled receipts. Dequeue oldest case eligible at a safe mutation boundary; prioritize author control/integrity/effect reconciliation over any writer, then known deterministic fix/review, then unrecognized trustworthy diagnosis. On concurrent cases, serialize without dropping the loser. New successful source revalidation can close a case; it cannot silently clear a distinct pending case.
- **Admission & proof**: all branch decisions in the existing `assess_recovery` node (C03); source proof from `trustedHead`, immutable checkpoints, plan/Turn grants, Pi responses, Repair ledger, author controls and native validation. No separate recovery graph, persistent semantic issue tracker, cost ledger, model provider switching or arbitrary controller patching. Use the existing `withStoryJobLock` and original pinned Pi sessions.
- **Stop semantics**: `pause` for actual author execution controls/question/protected decision or missing provider/budget, `integrity-fence` for untrusted/ambiguous effects with precise inspection, `exhausted` for genuine protocol/nonconvergence/resources after corroborated attempts; `completed` is **not** a RecoveryDecision. It is the existing independently validated completion verdict only with all obligations discharged.

**Concrete sequences to implement/certify**: (1) returned negative reviewer → sealed negative Review cycle → original-session correction → native/Git checkpoint → independently continued reviewer verdict → resolve Repair reference → selectively revalidate dependents → original `author_update_intake` and scheduling; (2) known protocol error → exact response-contract receipt, two tool-restricted original-session responses, eligible fresh bounded session only after proof of exhausted contract and effect reconciliation → original operation; (3) truthful Event/Interactive no-write or adaptive contradiction → authenticated assignment/plan source → existing known strategy or one started diagnostic → controller-authorized versioned amendment → original Turn proceeds; (4) ambiguous postcommit/precheckpoint interruption → original receipt + Git/Pi reconciliation without replay; (5) cancelled, protected, exhausted or tampered → durable proof-backed stop; (6) same checkpoint/case inspected or resumed repeatedly → no second Pi attempt, duplicated correction, changed scope, reset budget or repeated commit.

## State transitions and adapter handoff (normative C02–C08 protocol)

**Schema authority:** The enumerations and fields in [`src/generation-recovery-contract.ts`](../src/generation-recovery-contract.ts) are a compile-time mirror of **this** version-controlled specification, not an independent runtime state machine or a second normative design. C02 implements the graph annotation and compatibility reader from these definitions. Any conflict is resolved by updating **this document, the types, implementations and tests in one reviewed change**, subject to ADR 0002/0005/0006 and #197. Existing domain-specific receipts are effect authorities; the graph lifecycle stores *references only*. Do not introduce an independent case store, competing `RecoveryDecision` enums, new scheduler or arbitrary recovery worker.

**Invariants enforced at every transition:**

1. A case can be admitted only after identifying the original authenticated operation and check. `origin.jobThreadId` and `origin.graphThreadId` are different fields deliberately: require both to agree with original job and graph checkpoint. The original `turnDigest`, `planVersion`, assignment, `sourceHeadSha`, provenance and immutable evidence are never silently rebased. Null source/Turn is valid only for historical or preadmission *inspection*; a model diagnosis or writer dispatch requires trusted full identity. Do not fill nulls from model text.
2. The active lifecycle is a **routing projection**, not evidence of Pi/Git/Review work. A decision cannot itself claim a started or successful attempt. The `RecoveryAttempt` index records `caseId`, source-bound `invocationId`, purpose, tool mode, phase and `startedRef`/`settledRef`. `prepared`/queued has no invocation proof. `started` counts as a genuinely invoked correction-agent attempt *only* if the trusted original Pi receipt confirms model execution; `settled` additionally requires authenticated response/tool/usage receipts. A completed semantic writer correction counts as a submitted revision only after its existing source-bound submission receipt. A failed initial specialist, controller assessment and nonstarted planned diagnosis never satisfy the **one real attempt** guarantee.
3. Preserve the same model/provider and budget ledger, protected approvals, original author objective, current source-derived permissions and independent reviewer authority. All model calls are subject to resource admission. Before a new writer, inspect the job writer lock, existing original Pi session, claimed/committed effects, native checks and currently approved assignment. Never infer write authority from `action = plan-amendment`, a diagnostic recommendation, historical plan version or previous author signature.
4. Multiple cases are deduplicated by canonical identity; no case can overwrite another. An existing unresolved case for the same original operation/check and source is reopened **by reference**, not recreated with a fresh attempt allowance. Priority: cancellation/author control → integrity/source or ambiguous writer reconciliation → known deterministic correction and current Review-cycle work → controller-gated plan amendment → one warranted unfamiliar read-only diagnosis → independent unrelated progress. When two cases are mutually blocked, persist both and fence if no provably safe ordering exists. Only a verified resolution removes an active case, then the oldest eligible pending case is selected.
5. Each `RecoveryAdapterOutcome` must contain the same `caseId`; the existing `assess_recovery` controller matches it against current job/Thread/Turn/check/HEAD/receipts **before** accepting it. `prepared` is intent only; `reconciled` proves the original effect; `started` cites authenticated invocation; `verified` cites native/Git/independent source assurance; `stopped` has a typed, justified nonrepair disposition. No adapter can claim the whole Turn completed.

| State → event | Preconditions (controller authenticates) | Persisted decision / side effects | Next legal phase and graph edge |
| --- | --- | --- | --- |
| `idle` → failure/refusal | Admitted Turn; failed check/result source identified or explicit unsafe identity | Persist single case plus original evidence links; do not dispatch before checkpoint | `assessing` → existing `assess_recovery`; source-absent cases fence |
| `assessing` → verified known correction | Exact original result/response, authorized scope, existing adapter and budget | `known-correction`; link original Review/response-contract/fix receipt, not copy it | `correcting` → adapter; `verifying` after real effect; never end as blocked solely for missing ad hoc handler |
| `assessing` → cross-owner/Blueprint/adaptive plan change | Sealed defect/no-write proof, plan version, owner and protected-scope gate | `plan-amendment`; verified amendment may later be admitted under existing work-plan authority | `correcting` only after controller authorization; else genuine `paused` for protected choice; C06 |
| `assessing` → unfamiliar trustworthy semantic failure | No suitable known path; complete trusted immutable source; original effects reconciled; no relevant authenticated diagnostic already started; budget/provider available | `diagnostic` with `attemptRef = null`, then durable invocation admission and actual started receipt in original job | `diagnosing`; successful advice must return to controller admission; no direct model-granted write |
| `assessing` → uncertain original effect | Claimed Pi/tool/commit/idea dispatch may have executed | `reconcile-effects` referencing original receipt and verified HEAD, no new writer grant | `reconciling`; `verifying` if settled, otherwise `fenced` with exact ambiguous-operation proof |
| `assessing` → independent continuation | Original failure settled **no-write**, blocked assignment and its dependents recorded, HEAD unchanged, independent assignments proved | `continue-independent` referencing inventory and failed original assignment | Existing `author_update_intake`/schedule; keep unresolved case pending, and forbid final completion until corrected |
| Any active phase → resource/author control | Real author control, protected approval, verified budget/provider ineligibility | `pause` with original question/control/budget receipt and required next action; do not consume correction allowance | `paused`; only exact controller-authorized resume, then source recheck |
| `diagnosing`/`correcting` → invocation began | Pinned Pi session and attempt receipt, source unchanged, correct tools and model, budget gate | `RecoveryAttempt.phase = started`; store authenticated original invocation ID and receipt link before further progression | Remain active; on restart *inspect* the existing operation, never issue same prompt again |
| `diagnosing`/`correcting` → settled model/result | Pi transcript and externally persisted effect authenticated, original plan/HEAD checked | Settle attempt reference; controller independently validates proposed owner/scope; writer creates original domain receipt, not graph-owned Story content | `verifying` or new `plan-amendment`/Review strategy; invalid claim is not a pass |
| `verifying` → accepted corrected state | Current native/Git proof, required independent reviewer verdict, causal dependent revalidation, author control and no outstanding obligation for that case | `verified` adapter result; link changed/current checkpoint and historical originals | `resolved` → next queued case or original `author_update_intake` → normal scheduler |
| `verifying` → still failing | Same source-linked obligation remains, new scoped finding, or nonconverging review | Preserve prior attempts and original failed review; re-evaluate convergence and new source/check identity | `assessing` for next authorized strategy; `exhausted` only for proven semantic stagnation/resources or bounded protocol exhaustion |
| Any phase → untrustworthy identity/unsafe effects | Missing/tampered approval/checkpoint, unexplained HEAD change, in-flight writer or inconsistent source | `integrity-fence` with precise evidence and reconciliation action; never interpret unknown as a safe new invocation | `fenced`; inspect same Thread/receipts, no auto replay |
| Final decision after recovered work | All cases resolved, latest work-plan inventory and Turn objective complete, no negative Review/Repair/author/revalidation obligations, native/Git and current reviewer passes | **No RecoveryDecision claims completion**; ordinary `completion_decision` owns success | Existing graph `completed` / `END`; any unmet obligation reenters assessment |

**Strategy adapter boundary:** C03 normalizes each observed failure to `RecoveryCase`, invokes the existing `assess_recovery` decision boundary, selects a single typed `RecoveryDecision`, and dispatches the *original* appropriate adapter. Each adapter takes the immutable case, chosen decision, current authoritative job/Turn/source, and already-linked receipts; returns one `RecoveryAdapterOutcome` (`prepared | reconciled | started | verified | stopped`). Each adapter must re-read trusted effect/source receipts immediately before action, declare whether a writer can possibly have run, and return **receipt references**, never self-asserted approvals or user-facing exception text as a classification. All actions that change canonical Story work remain governed by existing specialist owner, the graph's original job lock, native validation and independent review. This interface does **not** require replacing each domain function with new infrastructure; C04–C07 wrap or adapt these existing seams: `recoverResponseContract`; `advanceRejectedRepair` and independent reviewer; `advanceReviewDependency`, `advanceCrossDomainCloseout`, `inspectCausalAmendment`, `reconcileAdaptiveWork`; `diagnoseUnknownCompletion` (C05 replaces advisory-only disposition); `reconcileRecoveryCheckpoints`; `revalidateOtherOwnerPrerequisite`; and `inspectBlockedOriginalThreadCorrection`.

### Replay / migration safety decision table

| Original saved operation/effect | On restart: safe proof | Automatically allowed | Forbidden until reconciled |
| --- | --- | --- | --- |
| No invocation receipt; explicitly proven unstarted | Exact original assignment, model/plan, unchanged HEAD and no Pi/tool claims | Admit *the original* unstarted operation using its existing persistent identity | New unrelated writer or new authorization |
| Initial agent refused or returned no-write | Closed original session, explicit no-write receipt and unchanged source | Existing Review/plan/diagnostic correction, or independent assignments proven safe | Count initial refusal as correction; re-prompt original writer |
| Diagnostic planned but no started receipt | Current source, budget and absence of any ambiguous provider attempt | Reconcile admission and start **once** only if provably not invoked | Count queued/assessed work as attempt or reset invocation ID |
| Diagnostic started, response unconfirmed | Original session and tool/call logs, usage/pending provider state | Resume only supported original Pi/protocol continuation after proof | Issue a second model call merely because the parent checkpoint is old |
| Diagnostic settled with matching signature | Accepted original transcript/protocol receipt | Reuse read-only result and verify actionable controller proposal | Diagnose same source/check again or accept model advice as permission |
| Claimed writer or dirty tree | Original claimed session, work-item receipt and Git status | Reconcile exact original effects, possibly explicit author/manual inspection | Fresh writer, replacement session, staging dirty files as trusted work |
| Committed but parent checkpoint stale | Original signed commit intent, Git SHA/ancestry, native/Review receipt | Finalize/adopt *the original* commit idempotently, revalidate affected dependents | Duplicate commit, bypass independent Review, new plan grants |
| Paused Author Question or protected approval | Exact source-bound author question/signature; current job control | Resume only with existing typed author/control response | Derive approval from a model or legacy response |
| Protocol exhausted or v1 semantic counters | Source-bound response contract and historical receipts | Inspect old counts; enforce current protocol ceiling, ADR 0006 convergence for new semantic work | Reset invocation history; treat historical 2/3/12 counters as new semantic limits |
| Malformed/tampered legacy channel or contradictory two channels | Original immutable checkpoint and receipt inspection, neither silently discarded | Read-only projection/fence with evidence refs; explicit correction of provenance | Choose one by convenience, erase competing case, replay stale Pi/commit |
| Completed old graph | Current verified HEAD, completed inventory, Review/Turn report and no pending work | Read-only completion projection | Import an old completed flag as authorization to skip current required checks |

## Maintained CI gate and residual work

[The test](../test/generation-recovery-coverage.test.ts) parses the **actual TypeScript AST** for all ten `addNode` callbacks and corresponding `addConditionalEdges`, for the declared typed `Operation` checks, for actual conditional-edge routing predicates and their END destinations, and for direct terminal-status returns, `blocked()`, `operationFailure()`, `authorBoundary()`, `reconcile()` and throws in those nodes plus the major shared exit helpers and public CLI entrypoint. It compares reviewed *per-site* structural counts. A new graph node, END edge, operation label, direct status/throw/recovery branch changes the expected snapshot and **fails CI** until the developer audits its evidence/adapter/disposition and updates this table with the test baseline. The test is source-coverage maintenance, **not** proof of runtime correction or dynamic control-flow soundness. C08 must strengthen it with deterministic production graph + Git / postcheckpoint / real-Pi certification and exhaustive negative return variants. Any changed helper calls, deep indirect exceptions or external Studio HTTP/queue faults that this AST inventory cannot detect are specifically covered by C08 behavioral fixtures; outer queue/HTTP self-healing and OS crashes remain out of scope.

Known migration gaps are explicit in the matrix: direct terminal author/scope escalation, no-write Event/Interactive-to-adaptive contradictions, essential blocked specialist with independent continuation only, an unknown diagnostic that is advisory-only, competing assessment phases, potential uncaught pretry job reads, and Studio intent inferred from reason prose. **C01 specifies those gaps but intentionally does not implement them.** #197 is not complete when C01 lands; C02–C08 must close them and prove one genuine diagnostic/correction attempt before calling recoverable failures terminal.

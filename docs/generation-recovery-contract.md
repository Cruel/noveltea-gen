Status: **C01 normative contract, C02 current-format graph cutover**. Historical beta checkpoint upgrades are explicitly out of scope. Parent [#197](https://github.com/Cruel/noveltea-gen/issues/197). Complements (does not replace) [the #225 exit inventory](recovery-exit-inventory.md). Subsequent work is sequenced #239 (C02) → #240 (C03) → #241/#242 (C04/C05) → #243 (C06) → #244 (C07) → #245 (C08).

## Non-negotiable boundary and authority

ADR [0002](adr/0002-goal-driven-story-orchestration.md): one goal-driven **production** graph and trusted controller; model proposals do not authorize writes. ADR [0005](adr/0005-bounded-correction-and-recovery.md) as **superseded in part** by [0006](adr/0006-persistent-review-and-incremental-story-blueprints.md): original Pi writer and persistent independent read-only reviewer conversations, semantic convergence and resources, no mandatory fresh reviewer per correction, no fixed 2/3/12 ordinary semantic attempt cutoff, no cross-review matching of creative issue identities. The existing bounded protocol counters and author grants in [repair-ledger.ts](../src/repair-ledger.ts) remain authoritative for their own current receipts; no checkpoint-format adapter is required. Separate bounded protocol response retries (two corrections after original, at most one authorized fresh invocation), infrastructure retries, integrity checks and job Pi budget ceilings still apply. Review disagreement, repeated nonprogress and oscillation require a distinct independent diagnosis/strategy, not automatic acceptance.

**Invariant:** Within an admitted autonomous generation Turn, a recoverable unresolved problem cannot become terminal **only** because no per-case handler was registered. First validate source/effects, author control, and existing deterministic correction/review/Repair routes. If a trustworthy semantic/plan failure remains unfamiliar, route it through one **actually started** bounded read-only diagnostic/correction agent and the controller's independently validated correction proposal before considering a recoverable stop. A speculative decision, completed *initial failed specialist*, queued invocation, protocol assessment, or model recommendation with no proven invocation is **not** an agent correction attempt. Attempts are corroborated by the existing Pi invocation/start receipt and settled response (for correction work: a completed submitted revision); multiple probes of the same immutable source cannot reset them. Untrusted source/provenance, protected author approval, cancellation, pending genuine Author Question, exhausted resources/provider, uncertain writer effects, and nonconverging correction may pause/fence without a dangerous model call. A pure read-only diagnostic never confers a write lease, overrules a sealed negative review or marks the Story complete.

The type-only state contract is [generation-recovery-contract.ts](../src/generation-recovery-contract.ts). C02 implements one recovery authority in the production graph, with no additional live state channel.

## Typed identity, decision and lifecycle

- **Case**: `RecoveryCase.schema = noveltea-generation-recovery-case/v1`; closed cause `semantic | protocol | infrastructure | authorization | resource | execution-control | integrity`; explicit `observation` (throw/returned negative/preflight/refused review/incomplete/reconciliation); `effect` (no effect, read-only, settled no-write, verified committed, *uncertain writer*). Deeply immutable `origin`: job ID, original job Thread ID and actual LangGraph Thread ID, authenticated original Turn digest, pinned plan version (null only if its absence is independently proved), trusted **original** HEAD, bound assignment, original operation and versioned failed check, and an authenticated `failureAnchor` (`store`, `ref`, `failedCheckInstanceId`) taken from the **original failed-check execution**. `evidence[]` contains immutable store/ref/digest links to authentic existing receipts; `causedByCaseId` links but does not copy the ledger.
- **Canonical original-failure identity**: `RecoveryCase.id = SHA-256(canonical-v1 tuple (schema, jobId, jobThreadId, graphThreadId, turnDigest, planVersion, originalSourceHeadSha, assignmentId, operation, check, checkVersion, failureAnchor.store, failureAnchor.ref, failureAnchor.failedCheckInstanceId))`. Encode fields in exactly that order with unambiguous length-delimited/canonical serialization; no implicit undefined, object-key iteration, locale order or fallback to wall clock. The anchor MUST name a durable, authenticated *original failed operation/check invocation or original graph task/checkpoint*; the advancing resume cursor and freshly observed receipt never qualify. If the original failure has no dedicated result receipt, use the persisted original LangGraph task/checkpoint identity and exact failed-check identifier, not a newly generated admission UUID. **Kind, observation, evidence, case admission ordinal, new reviewer/diagnostic receipts, current HEAD, error text, proposed correction and model attempt count are NOT key material.** Admission evidence stays frozen; later observations are linked append-only through decisions/attempts and original stores without replacing the case or minting fresh entitlements. Before admitting, reconcile against unresolved and prior-case provenance keyed by this original failure anchor. Reinspection/restart/source revisions/reclassification of the **same unresolved obligation** reuse its original case ID and all prior model attempts, even if a new check observes it at a changed HEAD; revalidate changed HEAD and proven correction before resolving or superseding the original. A genuinely distinct authenticated failed-check invocation may establish a new case, but first reconcile whether it merely repeats the previous unresolved obligation; linked work retains convergence history and cannot reset correction limits. Missing, conflicting or untrusted identity produces a **separate inspection-only fence** with no case ID, NEVER a fabricated `RecoveryCase`. Revalidate trusted HEAD/check/source before any effects or original blocked-Thread reentry.
- **Untrusted admission**: `RecoveryAdmission` is the exclusive `admitted(case) | fenced(fence)` result. `RecoveryInspectionFence.schema = noveltea-generation-recovery-inspection-fence/v1` retains immutable observed-but-**untrusted** origin fields, original checkpoint pointer when available, receipt evidence, typed reason and required inspection. It has no `caseId`, no `RecoveryDecision`, no attempt, and no writer/model authority. `RecoveryLifecycle.inspectionFences[]` preserves simultaneous incompatible or pre-admission evidence without dropping competing claims; any unresolved inspection fence gates all mutation until an authenticated case can be established or the integrity issue is explicitly reconciled. An existing authenticated case that becomes unsafe can instead use `RecoveryDecision.action = integrity-fence`, retaining its genuine case ID.
- **Decision**: `RecoveryDecision.schema = noveltea-generation-recovery-decision/v1` with the exact case ID, checked HEAD and immutable evidence links. Its discriminated `action` is one of **known-correction**, **plan-amendment**, **diagnostic**, **reconcile-effects**, **continue-independent**, **pause**, **exhausted**, **integrity-fence**. Each has typed destination/required proof. `diagnostic.attemptRef` is null until an **actual** original model attempt starts; settled completion must be independently corroborated through the indexed `RecoveryAttempt` original invocation and Pi references. `plan-amendment` describes scope/owner but is **not** authorization. Only controller-granted, source-current specialist scopes and existing protection/approval gates can dispatch a writer.
- **Lifecycle**: `RecoveryLifecycle.schema = noveltea-generation-recovery/v1`, one active authenticated case, a stable pending queue of distinct cases, a separate durable array of unauthenticated inspection fences, one decision (only for the active case), one original-invocation `RecoveryAttempt` reference (or null), phase `idle → assessing → reconciling | diagnosing | correcting → verifying → resolved → idle`, plus explicit `paused` or `fenced`. Persist a phase **before** an irreversible side effect and preserve links to the original started/settled receipts. Dequeue oldest case eligible at a safe mutation boundary; prioritize author control/integrity/effect reconciliation over any writer, then known deterministic fix/review, then unrecognized trustworthy diagnosis. On concurrent cases, serialize without dropping the loser. New successful source revalidation can close a case; it cannot silently clear a distinct pending case.
- **Admission & proof**: all branch decisions in the existing `assess_recovery` node (C03); source proof from `trustedHead`, immutable checkpoints, plan/Turn grants, Pi responses, Repair ledger, author controls and native validation. No separate recovery graph, persistent semantic issue tracker, cost ledger, model provider switching or arbitrary controller patching. Use the existing `withStoryJobLock` and original pinned Pi sessions.
- **Stop semantics**: `pause` for actual author execution controls/question/protected decision or missing provider/budget, `integrity-fence` for untrusted/ambiguous effects with precise inspection, `exhausted` for genuine protocol/nonconvergence/resources after corroborated attempts; `completed` is **not** a RecoveryDecision. It is the existing independently validated completion verdict only with all obligations discharged.

**Concrete sequences to implement/certify**: (1) returned negative reviewer → sealed negative Review cycle → original-session correction → native/Git checkpoint → independently continued reviewer verdict → resolve Repair reference → selectively revalidate dependents → original `author_update_intake` and scheduling; (2) known protocol error → exact response-contract receipt, two tool-restricted original-session responses, eligible fresh bounded session only after proof of exhausted contract and effect reconciliation → original operation; (3) truthful Event/Interactive no-write or adaptive contradiction → authenticated assignment/plan source → existing known strategy or one started diagnostic → controller-authorized versioned amendment → original Turn proceeds; (4) ambiguous postcommit/precheckpoint interruption → original receipt + Git/Pi reconciliation without replay; (5) cancelled, protected, exhausted or tampered → durable proof-backed stop; (6) same checkpoint/case inspected or resumed repeatedly → no second Pi attempt, duplicated correction, changed scope, reset budget or repeated commit.

## State transitions and adapter handoff (normative C02–C08 protocol)

**Schema authority:** The enumerations and fields in [`src/generation-recovery-contract.ts`](../src/generation-recovery-contract.ts) are a compile-time mirror of **this** version-controlled specification, not an independent runtime state machine or a second normative design. C02 implements the graph annotation and current-checkpoint verifier from these definitions. Any conflict is resolved by updating **this document, the types, implementations and tests in one reviewed change**, subject to ADR 0002/0005/0006 and #197. Existing domain-specific receipts are effect authorities; the graph lifecycle stores *references only*. Do not introduce an independent case store, competing `RecoveryDecision` enums, new scheduler or arbitrary recovery worker.

**Invariants enforced at every transition:**

1. An authenticated `RecoveryCase` can be admitted only after verifying the original failed-check instance/anchor AND its immutable operation/check/HEAD/Turn provenance from existing stores. `origin.jobThreadId` and `origin.graphThreadId` are different fields deliberately: require both to agree with the original job and graph checkpoint. The original `turnDigest`, `planVersion`, assignment, `sourceHeadSha`, `failureAnchor`, and evidence are deeply readonly, never silently rebased. Absent/untrusted source, Turn or failure anchor is valid only in `RecoveryInspectionFence.observedOrigin`; do not manufacture a trusted case or fill blanks from model text. Null plan version or assignment in a trusted case requires corroborated absence. No inspection fence can flow to diagnosis, correction or completion.
2. The active lifecycle is a **routing projection**, not evidence of Pi/Git/Review work. A decision cannot itself claim a started or successful attempt. The `RecoveryAttempt` index records `caseId`, source-bound `invocationId`, purpose, tool mode, phase and `startedRef`/`settledRef`. `prepared`/queued has no invocation proof. `started` counts as a genuinely invoked correction-agent attempt *only* if the trusted original Pi receipt confirms model execution; `settled` additionally requires authenticated response/tool/usage receipts. A completed semantic writer correction counts as a submitted revision only after its existing source-bound submission receipt. A failed initial specialist, controller assessment and nonstarted planned diagnosis never satisfy the **one real attempt** guarantee.
3. Preserve the same model/provider and budget ledger, protected approvals, original author objective, current source-derived permissions and independent reviewer authority. All model calls are subject to resource admission. Before a new writer, inspect the job writer lock, existing original Pi session, claimed/committed effects, native checks and currently approved assignment. Never infer write authority from `action = plan-amendment`, a diagnostic recommendation, historical plan version or previous author signature.
4. Deduplication first resolves the **authenticated original failure anchor** against existing active/pending and previously settled source-bound cases; it is not merely hashing each newly observed evidence bundle. No case can overwrite another. Repeated checks of the same unresolved obligation (including changed source or new receipts) reopen the original case **by reference**, preserving every started invocation, Review/Repair cycle and convergence budget. A new case requires a distinct independently authenticated failed-check occurrence and reconciliation of its relationship to unresolved predecessor obligations, not just a changed HEAD or classification. Priority: cancellation/author control → integrity/source or ambiguous writer reconciliation → known deterministic correction and current Review-cycle work → controller-gated plan amendment → one warranted unfamiliar read-only diagnosis → independent unrelated progress. When two cases are mutually blocked, persist both and fence if no provably safe ordering exists. Only a verified resolution removes an active case, then the oldest eligible pending case is selected.
5. Each `RecoveryAdapterOutcome` must contain the same `caseId`; the existing `assess_recovery` controller matches it against current job/Thread/Turn/check/HEAD/receipts **before** accepting it. `prepared` is intent only; `reconciled` proves the original effect; `started` cites authenticated invocation; `verified` cites native/Git/independent source assurance; `stopped` has a typed, justified nonrepair disposition. No adapter can claim the whole Turn completed.

| State → event | Preconditions (controller authenticates) | Persisted decision / side effects | Next legal phase and graph edge |
| --- | --- | --- | --- |
| `idle` → authenticated failure/refusal | Admitted Turn, trusted failed-check anchor and original job/Thread/Turn/HEAD/operation proof; dedup against existing case history | Reuse existing case or persist one new authenticated case with immutable original proof; do not dispatch before checkpoint | `assessing` → existing `assess_recovery` |
| `idle`/any phase → untrusted *preadmission* failure | Missing, unsupported or contradictory original identity/anchor/current checkpoint; trusted case not constructible | Persist `RecoveryInspectionFence` with observed untrusted fields, original available receipt links and required inspection; **no case ID/decision/attempt** | `fenced` read-only; resume only after provenance explicitly authenticated and case admission rechecked |
| `assessing` → verified known correction | Exact original result/response, authorized scope, existing adapter and budget | `known-correction`; link original Review/response-contract/fix receipt, not copy it | `correcting` → adapter; `verifying` after real effect; never end as blocked solely for missing ad hoc handler |
| `assessing` → cross-owner/Blueprint/adaptive plan change | Sealed defect/no-write proof, plan version, owner and protected-scope gate | `plan-amendment`; verified amendment may later be admitted under existing work-plan authority | `correcting` only after controller authorization; else genuine `paused` for protected choice; C06 |
| `assessing` → unfamiliar trustworthy semantic failure | No suitable known path; complete trusted immutable source; original effects reconciled; no relevant authenticated diagnostic already started; budget/provider available | `diagnostic` with `attemptRef = null`, then durable invocation admission and actual started receipt in original job | `diagnosing`; successful advice must return to controller admission; no direct model-granted write |
| `assessing` → uncertain original effect | Claimed Pi/tool/commit/idea dispatch may have executed | `reconcile-effects` referencing original receipt and verified HEAD, no new writer grant | `reconciling`; `verifying` if settled, otherwise `fenced` with exact ambiguous-operation proof |
| `assessing` → independent continuation | Original failure settled **no-write**, blocked assignment and its dependents recorded, HEAD unchanged, independent assignments proved | `continue-independent` referencing inventory and failed original assignment | Existing `author_update_intake`/schedule; keep unresolved case pending, and forbid final completion until corrected |
| Any active phase → resource/author control | Real author control, protected approval, verified budget/provider ineligibility | `pause` with original question/control/budget receipt and required next action; do not consume correction allowance | `paused`; only exact controller-authorized resume, then source recheck |
| `diagnosing`/`correcting` → invocation began | Pinned Pi session and attempt receipt, source unchanged, correct tools and model, budget gate | `RecoveryAttempt.phase = started`; store authenticated original invocation ID and receipt link before further progression | Remain active; on restart *inspect* the existing operation, never issue same prompt again |
| `diagnosing`/`correcting` → settled model/result | Pi transcript and externally persisted effect authenticated, original plan/HEAD checked | Settle attempt reference; controller independently validates proposed owner/scope; writer creates original domain receipt, not graph-owned Story content | `verifying` or new `plan-amendment`/Review strategy; invalid claim is not a pass |
| `verifying` → accepted corrected state | Current native/Git proof, required independent reviewer verdict, causal dependent revalidation, author control and no outstanding obligation for that case | `verified` adapter result; link changed/current checkpoint and historical originals | `resolved` → next queued case or original `author_update_intake` → normal scheduler |
| `verifying` → still failing | Same source-linked obligation remains, new scoped finding, or nonconverging review | Match original failure anchor and outstanding obligation before considering new-case admission; preserve prior attempts and Review/Repair lineage through source changes; independently verify genuinely distinct failed-check occurrence | `assessing` for next authorized strategy; `exhausted` only for proven semantic stagnation/resources or bounded protocol exhaustion |
| Any phase → untrustworthy identity/unsafe effects | Missing/tampered approval/checkpoint, unexplained HEAD change, in-flight writer or inconsistent source | `integrity-fence` with precise evidence and reconciliation action; never interpret unknown as a safe new invocation | `fenced`; inspect same Thread/receipts, no auto replay |
| Final decision after recovered work | All cases resolved, latest work-plan inventory and Turn objective complete, no negative Review/Repair/author/revalidation obligations, native/Git and current reviewer passes | **No RecoveryDecision claims completion**; ordinary `completion_decision` owns success | Existing graph `completed` / `END`; any unmet obligation reenters assessment |

**Strategy adapter boundary:** C03 first produces `RecoveryAdmission` with a **trusted case or a proof-bearing inspection fence**; it may invoke the existing `assess_recovery` decision boundary **only for a trusted case**, selects a single typed `RecoveryDecision`, and dispatches the *original* appropriate adapter. Each adapter takes the immutable case, chosen decision, current authoritative job/Turn/source, and already-linked receipts; returns one `RecoveryAdapterOutcome` (`prepared | reconciled | started | verified | stopped`). Each adapter must re-read trusted effect/source receipts immediately before action, declare whether a writer can possibly have run, and return **receipt references**, never self-asserted approvals or user-facing exception text as a classification. All actions that change canonical Story work remain governed by existing specialist owner, the graph's original job lock, native validation and independent review. This interface does **not** require replacing each domain function with new infrastructure; C04–C07 wrap or adapt these existing seams: `recoverResponseContract`; `advanceRejectedRepair` and independent reviewer; `advanceReviewDependency`, `advanceCrossDomainCloseout`, `inspectCausalAmendment`, `reconcileAdaptiveWork`; `diagnoseUnknownCompletion` (C05 replaces advisory-only disposition); `reconcileRecoveryCheckpoints`; `revalidateOtherOwnerPrerequisite`; and `inspectBlockedOriginalThreadCorrection`.

### C02 implementation mapping (one current-format lifecycle)

[`generation.ts`](../src/generation.ts) persists exactly one graph recovery authority, `recoveryLifecycle: RecoveryLifecycle`, and phase-free `recoverySources` bound to original domain receipts. The three domain-specific `recovery`, `operationRecovery` and `unknownRecovery` graph annotations and route predicates are removed. Existing domain adapters still consume local, **nonpersisted** projections while later tickets consolidate their execution. The graph does not create new writer, Pi, Review or approval permissions.

C02 handles **only the current checkpoint layout**. We intentionally do not migrate or read checkpoints generated by superseded beta graph schemas. Development/test databases and incomplete beta jobs may be recreated; changing the active schema does not require a historical upgrader. Kysely's unrelated application-database migrations remain untouched. Current-format process restarts must preserve original task, Job/Thread/Turn, budget, source and Pi/Review effects without replay.

| Transition | Implementation | Required current-format proof |
| --- | --- | --- |
| Original failed check → `assessing` | `originalGraphFailureAnchor`, `recoveryAdmission`, `applyDomainRecovery` | LangGraph executing task ID, parent checkpoint, authenticated Turn/plan/HEAD and original domain receipt |
| Simultaneous failures | `admitRecovery`, `selectPendingRecovery` | Distinct original failed-task identities queued, not overwritten; a resolved task cannot be admitted again |
| Assessment → decision | `decideExistingRecovery`, `decideRecovery` | One typed decision checkpointed before original adapter execution; effects stay with their original owner |
| Original reconciliation → verification → completion | `applyDomainRecovery`, `finishRecovery` | Authenticated original effect, eligible current native/Git/independent Review receipt; uncertain writer fenced, never replayed |
| Author/resource pause | `resumePausedRecovery`, existing job controls | Authenticated original author choice and budget; no model-generated approval |
| Current-format process restart | `verifyRecoveryCheckpoint`, `inspectModernGenerationRecovery` | Validate saved decision/phase/case, original persisted task, source and Pi receipts; reject forged or incomplete proofs |
| CLI/Studio inspection | `projectRecoveryInspection` | Read-only current-state projection with no sensitive Pi transcript exposure |

[Current-format tests](../test/generation-recovery-graph.test.ts), [lifecycle tests](../test/generation-recovery-lifecycle.test.ts) and [production restart tests](../test/generation.test.ts) exercise these invariants. The [AST coverage gate](../test/generation-recovery-coverage.test.ts) audits each production recovery node and exit through the shared boundary. C03–C08 implement additional correction strategies and end-to-end certification, not historical checkpoint migration.

### Replay and current-execution safety decision table

| Original saved operation/effect | On restart: safe proof | Automatically allowed | Forbidden until reconciled |
| --- | --- | --- | --- |
| No invocation receipt; explicitly proven unstarted | Exact original assignment, model/plan, unchanged HEAD and no Pi/tool claims | Admit *the original* unstarted operation using its existing persistent identity | New unrelated writer or new authorization |
| Initial agent refused or returned no-write | Closed original session, explicit no-write receipt and unchanged source | Existing Review/plan/diagnostic correction, or independent assignments proven safe | Count initial refusal as correction; re-prompt original writer |
| Diagnostic planned but no started receipt | Current source, budget and absence of any ambiguous provider attempt | Reconcile admission and start **once** only if provably not invoked | Count queued/assessed work as attempt or reset invocation ID |
| Diagnostic started, response unconfirmed | Original session and tool/call logs, usage/pending provider state | Resume only supported original Pi/protocol continuation after proof | Issue a second model call merely because the parent checkpoint is old |
| Diagnostic settled with matching signature | Accepted original transcript/protocol receipt | Reuse read-only result and verify actionable controller proposal | Diagnose same source/check again or accept model advice as permission |
| Claimed writer or dirty tree | Original claimed session, work-item receipt and Git status | Reconcile exact original effects, possibly explicit author/manual inspection | Fresh writer, replacement session, staging dirty files as trusted work |
| Committed but parent checkpoint stale | Original signed commit intent, Git SHA/ancestry, native/Review receipt | Finalize/adopt *the original* commit idempotently, revalidate affected dependents | Duplicate commit, bypass independent Review, new plan grants |
| Paused Author Question or protected approval | Exact source-bound author question/signature; current job control | Resume only with existing typed author/control response | Derive approval from a model or unverified response |
| Protocol exhausted or v1 semantic counters | Source-bound response contract and historical receipts | Inspect old counts; enforce current protocol ceiling, ADR 0006 convergence for new semantic work | Reset invocation history; treat historical 2/3/12 counters as new semantic limits |
| Malformed/tampered current case or contradictory concurrent failures | Original immutable checkpoint and receipt inspection, neither silently discarded | Preserve one or more `RecoveryInspectionFence` records without inventing a case ID; read-only inspection until exact original anchor/Turn/HEAD is authenticated | Choose one by convenience, erase competing case, replay stale Pi/commit |
| Completed old graph | Current verified HEAD, completed inventory, Review/Turn report and no pending work | Read-only completion projection | Import an old completed flag as authorization to skip current required checks |

## Legend for exhaustive source exit matrix

## Maintained CI gate and residual work

[The graph audit](../test/generation-recovery-coverage.test.ts) parses the **real production TypeScript AST** and independently gates: all ten `.addNode` callbacks and `.addConditionalEdges` source/target route signatures; the original `START → schedule` **direct graph edge** and any new `.addEdge`; the actual body of shared `routeAfterOperationAssessment` (not just its call arguments); the declared `Operation` checks; and every return, throw and status property (including computed statuses, nested lambdas and concise-arrow fences) in those nodes, major shared exit helpers and CLI entrypoint. The checked-in [reviewed exit baseline](../test/generation-recovery-exit-baseline.ts) gives each exit a stable **source-specific ID** `owner/return#N`, `owner/throw#N`, or `owner/status#N`, a normalized statement fingerprint, and an explicit disposition: **G** graph progress, **R** original recovery assessment, **O** unresolved obligation requiring later correction, **F** currently direct blocked/fenced gap, **U** author/resource stop, **B** conditional blocked/pause, **S** conditional control stop, **V** independently gated completion, **X** throw requiring boundary classification. These are observations of the **current** graph, not grants to continue or assertions that every F has been migrated; this matrix specifies its intended migration. Reviewed structural counts remain an additional check, not the sole guard. An altered return/status with the same count, a rewritten shared route helper, a changed direct edge, a new END edge, or a new operation fails CI pending explicit evidence/effect/adapter/disposition review. In-memory regression mutations demonstrate the previously missed bypasses. [Type-level regression tests](../test/generation-recovery-types.test.ts) also prove nested provenance/evidence readonly and prevent unsafe inspection fences from being treated as trusted cases. C02 MUST add executable original-failure-ID and source-aware dedup tests (changed/reordered/additional evidence, same unresolved obligation across revised HEAD and repeated resume, distinct authenticated failure, unsafe identity) when implementing the actual checkpoint reader/writer. The C01 AST and types tests are **not** runtime recovery or dynamic control-flow proof. C08 must add deterministic graph + Git/postcheckpoint/real-Pi certification and exhaustive negative return variants; deep indirect exceptions and external Studio HTTP/queue faults remain behavioral-fixture responsibilities, with outer queue/HTTP self-healing and OS crashes out of scope.

Known future correction-policy gaps are explicit in the matrix: direct terminal author/scope escalation, no-write Event/Interactive-to-adaptive contradictions, essential blocked specialist with independent continuation only, an unknown diagnostic that is advisory-only, competing assessment phases, potential uncaught pretry job reads, and Studio intent inferred from reason prose. **C01 specifies those gaps but intentionally does not implement them.** #197 is not complete when C01 lands; C02–C08 must close them and prove one genuine diagnostic/correction attempt before calling recoverable failures terminal.

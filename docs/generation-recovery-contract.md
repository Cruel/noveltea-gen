Status: **C01 normative contract, C02 current-format graph cutover**. Historical beta checkpoint upgrades are explicitly out of scope. Parent [#197](https://github.com/Cruel/noveltea-gen/issues/197). ## Non-negotiable boundary and authority

ADR [0002](adr/0002-goal-driven-story-orchestration.md): one goal-driven **production** graph and trusted controller; model proposals do not authorize writes. ADR [0005](adr/0005-bounded-correction-and-recovery.md) as **superseded in part** by [0006](adr/0006-persistent-review-and-incremental-story-blueprints.md): original Pi writer and persistent independent read-only reviewer conversations, semantic convergence and resources, no mandatory fresh reviewer per correction, no fixed 2/3/12 ordinary semantic attempt cutoff, no cross-review matching of creative issue identities. The existing bounded protocol counters and author grants in [repair-ledger.ts](../src/repair-ledger.ts) remain authoritative for their own current receipts; no checkpoint-format adapter is required. Separate bounded protocol response retries (two corrections after original, at most one authorized fresh invocation), infrastructure retries, integrity checks and job Pi budget ceilings still apply. Review disagreement, repeated nonprogress and oscillation require a distinct independent diagnosis/strategy, not automatic acceptance.

**Invariant:** Within an admitted autonomous generation Turn, a recoverable unresolved problem cannot become terminal **only** because no per-case handler was registered. First validate source/effects, author control, and existing deterministic correction/review/Repair routes. If a trustworthy semantic/plan failure remains unfamiliar, route it through one **actually started** bounded read-only diagnostic/correction agent and the controller's independently validated correction proposal before considering a recoverable stop. A speculative decision, completed *initial failed specialist*, queued invocation, protocol assessment, or model recommendation with no proven invocation is **not** an agent correction attempt. Attempts are corroborated by the existing Pi invocation/start receipt and settled response (for correction work: a completed submitted revision); multiple probes of the same immutable source cannot reset them. Untrusted source/provenance, protected author approval, cancellation, pending genuine Author Question, exhausted resources/provider, uncertain writer effects, and nonconverging correction may pause/fence without a dangerous model call. A pure read-only diagnostic never confers a write lease, overrules a sealed negative review or marks the Story complete.

The type-only state contract is [generation-recovery-contract.ts](../src/generation-recovery-contract.ts). C02 implements one recovery authority in the production graph, with no additional live state channel.

## Typed identity, decision and lifecycle

- **Case**: `RecoveryCase.schema = noveltea-generation-recovery-case/v1`; closed cause `semantic | protocol | infrastructure | authorization | resource | execution-control | integrity`; explicit `observation` (throw/returned negative/preflight/refused review/incomplete/reconciliation); `effect` (no effect, read-only, settled no-write, verified committed, *uncertain writer*). Deeply immutable `origin`: job ID, original job Thread ID and actual LangGraph Thread ID, authenticated original Turn digest, pinned plan version (null only if its absence is independently proved), trusted **original** HEAD, bound assignment, original operation and versioned failed check, and an authenticated `failureAnchor` (`store`, `ref`, `failedCheckInstanceId`) taken from the **original failed-check execution**. `evidence[]` contains immutable store/ref/digest links to authentic existing receipts; `causedByCaseId` links but does not copy the ledger.
- **Canonical original-failure identity**: `RecoveryCase.id = SHA-256(canonical-v1 tuple (schema, jobId, jobThreadId, graphThreadId, turnDigest, planVersion, originalSourceHeadSha, assignmentId, operation, check, checkVersion, failureAnchor.store, failureAnchor.ref, failureAnchor.failedCheckInstanceId))`. Encode fields in exactly that order with unambiguous length-delimited/canonical serialization; no implicit undefined, object-key iteration, locale order or fallback to wall clock. The anchor MUST name a durable, authenticated *original failed operation/check invocation or original graph task/checkpoint*; the advancing resume cursor and freshly observed receipt never qualify. If the original failure has no dedicated result receipt, use the persisted original LangGraph task/checkpoint identity and exact failed-check identifier, not a newly generated admission UUID. **Kind, observation, evidence, case admission ordinal, new reviewer/diagnostic receipts, current HEAD, error text, proposed correction and model attempt count are NOT key material.** Admission evidence stays frozen; later observations are linked append-only through decisions/attempts and original stores without replacing the case or minting fresh entitlements. Before admitting, reconcile against unresolved and prior-case provenance keyed by this original failure anchor. Reinspection/restart/source revisions/reclassification of the **same unresolved obligation** reuse its original case ID and all prior model attempts, even if a new check observes it at a changed HEAD; revalidate changed HEAD and proven correction before resolving or superseding the original. A genuinely distinct authenticated failed-check invocation may establish a new case, but first reconcile whether it merely repeats the previous unresolved obligation; linked work retains convergence history and cannot reset correction limits. Missing, conflicting or untrusted identity produces a **separate inspection-only fence** with no case ID, NEVER a fabricated `RecoveryCase`. Revalidate trusted HEAD/check/source before any effects or original blocked-Thread reentry.
- **Untrusted admission**: `RecoveryAdmission` is the exclusive `admitted(case) | fenced(fence)` result. `RecoveryInspectionFence.schema = noveltea-generation-recovery-inspection-fence/v1` retains immutable observed-but-**untrusted** origin fields, original checkpoint pointer when available, receipt evidence, typed reason and required inspection. It has no `caseId`, no `RecoveryDecision`, no attempt, and no writer/model authority. `RecoveryLifecycle.inspectionFences[]` preserves simultaneous incompatible or pre-admission evidence without dropping competing claims; any unresolved inspection fence gates all mutation until an authenticated case can be established or the integrity issue is explicitly reconciled. An existing authenticated case that becomes unsafe can instead use `RecoveryDecision.action = integrity-fence`, retaining its genuine case ID.
- **Decision**: `RecoveryDecision.schema = noveltea-generation-recovery-decision/v1` with the exact case ID, checked HEAD and immutable evidence links. Its discriminated `action` is one of **known-correction**, **plan-amendment**, **diagnostic**, **diagnostic-stop**, **reconcile-effects**, **continue-independent**, **pause**, **exhausted**, **integrity-fence**. The authenticated `diagnostic-stop` disposition is operator intervention, **not** evidence corruption: it is nonwritable and cannot resolve a case or authorize another diagnosis. It MUST carry a reference to the original completed, read-only Pi response-contract receipt and its exact advisory action/category. On every restart, `inspectOriginalUnknownDiagnosis` checks the job-bound admission, original source signature, Pi transcript and sealed response. An absent, mismatched, incomplete or tampered receipt invalidates the saved disposition and becomes an inspection-only fence; the verifier never calls Pi. Each has typed destination/required proof. `diagnostic.attemptRef` is null until an **actual** original model attempt starts; settled completion must be independently corroborated through the indexed `RecoveryAttempt` original invocation and Pi references. `plan-amendment` describes scope/owner but is **not** authorization. Only controller-granted, source-current specialist scopes and existing protection/approval gates can dispatch a writer.
- **Lifecycle**: `RecoveryLifecycle.schema = noveltea-generation-recovery/v1`, one active authenticated case, a stable pending queue of distinct cases, append-only `discharged[]` references to later verified corrections for deferred cases, a separate durable array of unauthenticated inspection fences, one decision (only for the active case), one original-invocation `RecoveryAttempt` reference (or null), and an optional typed `assessorPending` flag persisted **inside this same lifecycle** to distinguish a checkpointed decision from the original assessor's execution. No `reason` string controls recovery graph routing. Phase `idle → assessing → reconciling | diagnosing | correcting → verifying → resolved → idle`, plus explicit `paused` or `fenced`. Persist a phase **before** an irreversible side effect and preserve links to the original started/settled receipts. Dequeue oldest case eligible at a safe mutation boundary; prioritize author control/integrity/effect reconciliation over any writer, then known deterministic fix/review, then unrecognized trustworthy diagnosis. On concurrent cases, serialize without dropping the loser. A later independently verified source correction discharges only its matching pending case through `dischargePendingRecovery`, retaining the original case and correction receipt in `discharged[]`. The reader must reauthenticate both the original failed LangGraph task and the later Git/Review or idea-placement receipt after process restart; a forged correction SHA, absent review or unverified idea remains unresolved/fenced. This is a case lifecycle reference, not another issue tracker or a write grant.
- **Admission & proof**: all branch decisions in the existing `assess_recovery` node (C03); source proof from `trustedHead`, immutable checkpoints, plan/Turn grants, Pi responses, Repair ledger, author controls and native validation. No separate recovery graph, persistent semantic issue tracker, cost ledger, model provider switching or arbitrary controller patching. Use the existing `withStoryJobLock` and original pinned Pi sessions.
- **Stop semantics**: `pause` for actual author execution controls/question/protected decision or missing provider/budget, `integrity-fence` for untrusted/ambiguous effects with precise inspection, `exhausted` for genuine protocol/nonconvergence/resources after corroborated attempts; `completed` is **not** a RecoveryDecision. It is the existing independently validated completion verdict only with all obligations discharged.

**Concrete sequences to implement/certify**: (1) returned negative reviewer → sealed negative Review cycle → original-session correction → native/Git checkpoint → independently continued reviewer verdict → resolve Repair reference → selectively revalidate dependents → original `author_update_intake` and scheduling; (2) known protocol error → exact response-contract receipt, two tool-restricted original-session responses, eligible fresh bounded session only after proof of exhausted contract and effect reconciliation → original operation; (3) truthful Event/Interactive no-write or adaptive contradiction → authenticated assignment/plan source → existing known strategy or one started diagnostic → controller-authorized versioned amendment → original Turn proceeds; (4) ambiguous postcommit/precheckpoint interruption → original receipt + Git/Pi reconciliation without replay; (5) cancelled, protected, exhausted or tampered → durable proof-backed stop; (6) same checkpoint/case inspected or resumed repeatedly → no second Pi attempt, duplicated correction, changed scope, reset budget or repeated commit.

## State transitions and adapter handoff (normative C02–C08 protocol)

**Schema authority:** The enumerations and fields in [`src/generation-recovery-contract.ts`](../src/generation-recovery-contract.ts) are a compile-time mirror of **this** version-controlled specification, not an independent runtime state machine or a second normative design. C02 implements the graph annotation and current-checkpoint verifier from these definitions. Any conflict is resolved by updating **this document, the types, implementations and tests in one reviewed change**, subject to ADR 0002/0005/0006 and #197. Existing domain-specific receipts are effect authorities; the graph lifecycle stores *references only*. Do not introduce an independent case store, competing `RecoveryDecision` enums, new scheduler or arbitrary recovery worker.

**Invariants enforced at every transition:**

1. An authenticated `RecoveryCase` can be admitted only after verifying the original failed-check instance/anchor AND its immutable operation/check/HEAD/Turn provenance from existing stores. `origin.jobThreadId` and `origin.graphThreadId` are different fields deliberately: require both to agree with the original job and graph checkpoint. The original `turnDigest`, `planVersion`, assignment, `sourceHeadSha`, `failureAnchor`, and evidence are deeply readonly, never silently rebased. Absent/untrusted source, Turn or failure anchor is valid only in `RecoveryInspectionFence.observedOrigin`; do not manufacture a trusted case or fill blanks from model text. Null plan version or assignment in a trusted case requires corroborated absence. No inspection fence can flow to diagnosis, correction or completion.
2. The active lifecycle is a **routing projection**, not evidence of Pi/Git/Review work. A decision cannot itself claim a started or successful attempt. The `RecoveryAttempt` index records `caseId`, source-bound `invocationId`, purpose, tool mode, phase and `startedRef`/`settledRef`. `prepared`/queued has no invocation proof. `started` counts as a genuinely invoked correction-agent attempt *only* if the trusted original Pi receipt confirms model execution; `settled` additionally requires authenticated response/tool/usage receipts. A completed semantic writer correction counts as a submitted revision only after its existing source-bound submission receipt. A failed initial specialist, controller assessment and nonstarted planned diagnosis never satisfy the **one real attempt** guarantee.
3. Preserve the same model/provider and budget ledger, protected approvals, original author objective, current source-derived permissions and independent reviewer authority. All model calls are subject to resource admission. Before a new writer, inspect the job writer lock, existing original Pi session, claimed/committed effects, native checks and currently approved assignment. Never infer write authority from `action = plan-amendment`, a diagnostic recommendation, historical plan version or previous author signature.
4. Deduplication first resolves the **authenticated original failure anchor** against existing active/pending and previously settled source-bound cases; it is not merely hashing each newly observed evidence bundle. No case can overwrite another. Repeated checks of the same unresolved obligation (including changed source or new receipts) reopen the original case **by reference**, preserving every started invocation, Review/Repair cycle and convergence budget. A new case requires a distinct independently authenticated failed-check occurrence and reconciliation of its relationship to unresolved predecessor obligations, not just a changed HEAD or classification. Priority: cancellation/author control → integrity/source or ambiguous writer reconciliation → known deterministic correction and current Review-cycle work → controller-gated plan amendment → one warranted unfamiliar read-only diagnosis → independent unrelated progress. When two cases are mutually blocked, persist both and fence if no provably safe ordering exists. Only a verified resolution removes an active case, then the oldest eligible pending case is selected. Independently deferred cases are a distinct lane: a later verified correction discharges the pending case directly instead of selecting it into the original assessor (whose blocked status and unchanged original HEAD are no longer true).
5. Each `RecoveryAdapterOutcome` must contain the same `caseId`; the existing `assess_recovery` controller matches it against current job/Thread/Turn/check/HEAD/receipts **before** accepting it. `prepared` is intent only; `reconciled` proves the original effect; `started` cites authenticated invocation; `verified` cites native/Git/independent source assurance; `stopped` has a typed, justified nonrepair disposition. No adapter can claim the whole Turn completed.

**Strategy adapter boundary:** C03 first produces `RecoveryAdmission` with a **trusted case or a proof-bearing inspection fence**; it may invoke the existing `assess_recovery` decision boundary **only for a trusted case**, selects a single typed `RecoveryDecision`, and dispatches the *original* appropriate adapter. Each adapter takes the immutable case, chosen decision, current authoritative job/Turn/source, and already-linked receipts; returns one `RecoveryAdapterOutcome` (`prepared | reconciled | started | verified | stopped`). Each adapter must re-read trusted effect/source receipts immediately before action, declare whether a writer can possibly have run, and return **receipt references**, never self-asserted approvals or user-facing exception text as a classification. All actions that change canonical Story work remain governed by existing specialist owner, the graph's original job lock, native validation and independent review. This interface does **not** require replacing each domain function with new infrastructure; C04–C07 wrap or adapt these existing seams: `recoverResponseContract`; `advanceRejectedRepair` and independent reviewer; `advanceReviewDependency`, `advanceCrossDomainCloseout`, `inspectCausalAmendment`, `reconcileAdaptiveWork`; `diagnoseUnknownCompletion` (C05 uses a typed, source-bound general proposal for current operation cases, retaining historical v1 inspection); `reconcileRecoveryCheckpoints`; `revalidateOtherOwnerPrerequisite`; and `inspectBlockedOriginalThreadCorrection`.

### C03 coordinator routing (implemented boundary and remaining adapters)

The exit matrix below describes the original node bodies. `observeNodeOutcome` now also covers their enclosing execution boundary. When no earlier adapter claimed the failure, a direct `blocked` result enters admission as `returned-failure`; an escaping node exception enters as `exception`. `nodeFailureSource` maps each production node to the original operation/check and evidence family. These are observations, not proof of no write. Author controls and resource pauses are not semantic failures. An unavailable job or a failure while inspecting an active case preserves inspection evidence instead of minting a new case. LangGraph interruption at the outer boundary is not converted into a corrective assignment.

`assess_recovery` checks current HEAD and original Turn provenance before checkpointing its selection. Original-operation adapters consume that decision; read-only scheduling/intake exception reconciliation cannot clear a returned negative result. A historical `safeAction` hint is not dispatch authority: selecting independent continuation requires matching the operation, observation, evidence family and original HEAD, and releasing work still requires the original receipt or blocked inventory under lock. The same source-derived `independentObligation` now governs deferred discharge, modern checkpoint inspection, and blocked original-Thread continuation; these no longer take the serialized `operationRecovery.safeAction` field as permission or as a veto over already authenticated original effects. The field remains in current-format receipts for compatibility/reporting until C04 completes its adapter migration, not as a second coordinator. The shared edge predicate has precedence over each ordinary node's `END`. Fixture-only final editorial verdicts remain deliberate non-Pi stops; they cannot create a fresh diagnostic entitlement or replace deferred idea cases. The production Review refusal test interrupts both before selection and after the selection checkpoint: a refusal preserves the assignment, costs zero correction attempts, and cannot advance the writer.

C03 now selects a source-bound `plan-amendment` for independently admitted Event-owned Milestone closeouts, and a single read-only `diagnostic` for recognized, authenticated unresolved Review, adaptive-admission, completion and settled Event no-write evidence. A clean Event `prerequisite-reported` that has exhausted its existing in-scope Event reassignment is no longer silently discarded as only a blocked inventory entry: `specialist_dispatch` admits the original `specialist-result` failure with its immutable Pi report digest, retains the blocked obligation, and routes to `assess_recovery`. Diagnosis first verifies the real original Event transcript, report payload, unchanged HEAD, plan, failed assignment and blocked inventory, refuses a preexisting typed causal amendment or protected author request, and never starts another Event writer. The same coordinator can diagnose an independently verified original specialist whose **read-only reviewer** throws a transport exception: the original reviewed native/Git checkpoint and unchanged result HEAD are required, and neither the old reviewer nor the writer is replayed. The production graph tests check assessor selection before any model call, one actually settled diagnostic Pi invocation for both source-proven failures, authenticated restart, and a forged original Event report that fences without replay. It invokes existing adapters rather than treating selection as execution. The diagnostic runs against the original Pi response contract, records a settled invocation receipt only after the original transcript is authenticated, and remains an operator-only stop. A restart rechecks the immutable original Review/response proof **and** the sealed Pi transcript and invocation; altering either denies restart without a new call. The production graph also tests author cancellation and pause, exhausted per-job model budget, later resumption of that same selected diagnosis, and source-bound no-replay behavior. For adaptive `known-correction`, the selected C02 decision returns directly to the existing original same-Pi-session protocol adapter; the retired assessment callback must not run again against its already-authorized projection. For an Event-owned closeout crash after its original Git commit but before the parent graph update, `inspectPublishedCloseoutCommit` reauthenticates the saved authored digest, original Pi session, exact parent, field-only diff, required trailers and clean worktree before promoting the closeout receipt to `committed`. The generic job `trustedHead` remains unchanged: an unpublished successor can pass modern recovery-checkpoint inspection **only for a selected, still-pending closeout** whose checkpointed original inventory, repair ID, Turn, plan, source and original authored/committed receipt all agree. The CLI skips generic pre-graph checkpoint reconciliation while this exact adapter owns the lane; the existing closeout reviewer/repair ledger still decides publication. An interrupted in-flight writer or independent reviewer is not treated as completed merely because a commit or session file exists. The closeout reviewer now records a SHA-256 binding of the transcript in the original Pi context **after** the independent verdict, required reads and accepted response have completed. After a process crash, a selected `reviewing` closeout with the exact original completed context, pinned skills/model, metered session, signed writer commit and matching source can recover the original verdict **without prompting another reviewer**. Unfinished sessions remain fenced. A subsequent saved `reviewed` phase reconciles the original sealed verdict and `verified` reconciles only a resolved, independently passed Repair ledger, including the precise window after publishing verified HEAD but before the parent LangGraph checkpoint. In every phase the original field-only Git parent, writer digest, reviewer proof and original inventory remain independently checked; read-only inspection cannot publish a successor or authorize Composition. The scripted production Pi-session test exercises successful correction, exhaustion, initial/terminal crash windows and tampered original transcripts.

**Reviewed C03 `verify_committed_work` exit change:** a fixture's `review-handoff` after a committed Choice/Puzzle unit is an outstanding independent Review, **not** an unsuccessful specialist write. The original graph now returns a nonsemantic blocked stop while that mandatory review is unsealed, without recording a synthetic `specialist-result` failure, and rechecks the existing `assertNativeReviewDependencies` on the *same* original work item when resumed. A sealed Choice review permits the original Puzzle unit to proceed without replaying Choice; the same applies to a sealed Puzzle review. The AST baseline tracks two new explicit return sites (blocked pending Review and verified handoff continuation), two new exception sites (invalid stage and failed independent gate), and their two status sites. A source-authenticated production-graph regression also proves that replacing a fixture Event's worker flag with `pi` cannot authorize an Event-owned Milestone closeout: the original reviewed checkpoint becomes invalid, the attempted repair is refused, and canonical Git HEAD stays unchanged. An offline scripted-Pi adapter regression separately starts and settles the *real* bounded closeout writer and distinct read-only independent reviewer, with canonical original-session/tool transcripts, exact field-only amendment, and controller-owned Git commit. A separate **successful production-graph end-to-end** regression now also starts with an actual Pi-authored, independently reviewed Event and source-bound Choice, preserves only real sealed prior-stage checkpoint receipts, runs the same original LangGraph Thread through `assess_recovery` selection with zero model calls, executes one original source-bound `plan-amendment`, obtains the Event owner's actual Pi Milestone-field correction and a new independent review, selectively revalidates affected original dependent assignments, and reenters the original Composition assignment in `running` state without replay. The test uses an in-process scripted model, not a live remote provider or sandbox-isolation certification.

**Source-authenticated read-only scheduling diagnosis:** an unfamiliar scheduler exception with the original LangGraph failed-task anchor, matching Turn/plan/current verified HEAD, unchanged complete inventory, no active writer, no pending idea/causal owner amendment, and no protected author escalation now selects `diagnostic` rather than the unverifiable original-specialist reconciliation fallback. Its extra `graph-checkpoint` evidence SHA-256 seals the original scheduling failure receipt and inventory; the assessor checkpoints the decision before exactly one actual read-only Pi call. Reinspection of the source proof authenticates the sealed diagnostic and settled invocation on restart. Altering the original inventory invalidates the diagnostic without a new call. Unknown specialist effects, pending original writers, ambiguous external integrations, author-update consent, and protected content remain outside this admission: C04/C05 must reconcile them rather than treat a clean Git HEAD as proof of no external effects.

**Selective revalidation transcript isolation:** the end-to-end regression exposed a genuine replay boundary: `preparePiContext` previously reused the same narrative review transcript for later dependent assignments in the same Pi context group, thereby appending the next reviewer turn to an already sealed independent verdict and invalidating that verdict's SHA-256 proof. `reviewNarrative` now accepts a controller-selected source-bound independent-review key; `revalidateAfterReviewedCorrection` supplies the exact correction successor SHA plus dependent ID. Each separate dependent has its **own** Pi file and context, while intentional same-session format correction retains its existing identity. The test checks independent original and dependent reviewer sessions, immutable per-dependent digest, completed revalidation receipt, verified HEAD, and normal Composition reentry.

### C05 current-format diagnostic strategy and legacy retirement

Current **operationRecovery** cases selected by C03 use the existing `diagnoseUnknownCompletion` Pi/protocol/session/budget implementation, with `generation.recovery-diagnostic.v2` and `noveltea-recovery-diagnostic-proposal/v1` instead of the historical completion-only v1 advisory. The source-proven proof reference and immutable case signature bind the strict proposal to the failed check; the bounded packet includes original Job/Thread/Turn, approved author objective/scope, current and prior verified Git heads, assignment/inventory, available adapters and existing findings/attempt references, not private author-only message history. Source-only selection happens before Pi invocation, and the model has **no tools**. Repeated unchanged diagnosis reads the sealed original transcript and completed protocol receipt, rather than prompting a new agent or resetting the job's budget ledger. Invalid proposals use the same response-contract correction as other read-only Pi responses. A model result is a proposed strategy, not a `RecoveryDecision` or a started attempt.

`generation-diagnostic-controller.ts` is a **pure adapter-admission projection** of the existing C03 assessor, not a new authority. Source-authenticated no-writer scheduling exceptions and transport errors after an already independently accepted assignment Review may select `reconcile-original` → existing `reconcile-effects`/`checkpoint-reconciliation`, but only with the original immutable HEAD/Turn/plan/assignment, sealed positive Review when applicable, no protected escalation and no new owner/scope grant. Before recording any verified resolution, the original assessor **reexecutes the scheduling check or reauthenticates the same independently passed original reviewer**, under the job lock. It then reauthenticates the sealed Pi proposal and attempt, original source, and Review/Turn assurance, and only the ordinary C02 `recordRecoveryOutcome` + `finishRecovery` transition may clear the case and resume scheduling. An original failure without its objective-planning seal, changed HEAD, missing original Review, or altered diagnostic transcript stays fenced; an accepted model answer is never enough. Other proposed strategies (`local-repair`, `dependency-plan`, `blueprint-or-work-plan-amend`, `review-adjudication`, `no-write-omission-review`) require their own C04/C06 original specialist/plan/Review authority and do not become permission simply because the model recommended them. `resource-or-author-pause`/`unsafe` also never grant work. Where the existing adapter cannot be independently authenticated, retain the unresolved case and sealed source-bound proposal in `diagnostic-stop`; the controller may later authorize a qualified original adapter but the saved opinion is not itself authorization. A saved stop must authenticate both original Pi result and source; a saved model-derived reconciliation independently rederives the same selected adapter and proposal. No second diagnostic retry loop is introduced.

Unexplained final-verdict anomalies now enter `completion-verification`/`operationRecovery` with an original report/status proof, instead of creating a separate active `unknownRecovery` case. `generation-final-verdict.ts` restricts inconsistent blocked-report anomalies to an otherwise independently passing Pi final review, completed scope and protected/author/resource gates; a different contradictory case (a final Pi report is complete but the Graph's original assignment inventory is incomplete) authenticates the original review, native checkpoint, current HEAD, Turn and scope before permitting **one read-only diagnosis**, not success. A negative or merely fixture-provided final result never creates a new diagnostic entitlement. The C02 Graph bridge rejects new legacy `unknownRecovery` admissions, but still projects historical v1 sources and reads existing legacy Pi receipts. The AST baseline tracks retired completion-only assessor returns and new C05/ C04 checked source transitions.

### C02 implementation mapping (one current-format lifecycle)

[`generation.ts`](../src/generation.ts) persists exactly one graph recovery authority, `recoveryLifecycle: RecoveryLifecycle`, and phase-free `recoverySources` bound to original domain receipts. The three domain-specific `recovery`, `operationRecovery` and `unknownRecovery` graph annotations and route predicates are removed. Existing domain adapters still consume local, **nonpersisted** projections while later tickets consolidate their execution. The graph does not create new writer, Pi, Review or approval permissions. Every recovery wrapper exit applies integrity/completion gates, even when the domain node emits no recovery update: a completed status is rejected whenever `active` or `pending` remains nonempty. `assessorPending` is the graph's typed dispatch indicator and replaces the former user-visible `reason` sentinel. Deferred no-write resolution belongs in `recoveryNode` at the authenticated schedule/intake boundary: verify the original failure and the *later* committed reviewer/native/idea-placement proof before appending `discharged[]`. Never rerun the original failed assessor against its obsolete `blocked` and unchanged-HEAD preconditions.

C02 handles **only the current checkpoint layout**. We intentionally do not migrate or read checkpoints generated by superseded beta graph schemas. Development/test databases and incomplete beta jobs may be recreated; changing the active schema does not require a historical upgrader. Kysely's unrelated application-database migrations remain untouched. Current-format process restarts must preserve original task, Job/Thread/Turn, budget, source and Pi/Review effects without replay.

## Maintained CI gate and residual work

[The graph audit](../test/generation-recovery-coverage.test.ts) parses the **real production TypeScript AST** and independently gates: all ten `.addNode` callbacks and `.addConditionalEdges` source/target route signatures; the original `START → schedule` **direct graph edge** and any new `.addEdge`; the actual body of shared `routeAfterOperationAssessment` (not just its call arguments); the declared `Operation` checks; and every return, throw and status property (including computed statuses, nested lambdas and concise-arrow fences) in those nodes, major shared exit helpers and CLI entrypoint. The checked-in [reviewed exit baseline](../test/generation-recovery-exit-baseline.ts) gives each exit a stable **source-specific ID** `owner/return#N`, `owner/throw#N`, or `owner/status#N`, a normalized statement fingerprint, and an explicit disposition: **G** graph progress, **R** original recovery assessment, **O** unresolved obligation requiring later correction, **F** currently direct blocked/fenced gap, **U** author/resource stop, **B** conditional blocked/pause, **S** conditional control stop, **V** independently gated completion, **X** throw requiring boundary classification. These are observations of the **current** graph, not grants to continue or assertions that every F has been migrated; this matrix specifies its intended migration. Reviewed structural counts remain an additional check, not the sole guard. An altered return/status with the same count, a rewritten shared route helper, a changed direct edge, a new END edge, or a new operation fails CI pending explicit evidence/effect/adapter/disposition review. In-memory regression mutations demonstrate the previously missed bypasses. [Type-level regression tests](../test/generation-recovery-types.test.ts) also prove nested provenance/evidence readonly and prevent unsafe inspection fences from being treated as trusted cases. C02 MUST add executable original-failure-ID and source-aware dedup tests (changed/reordered/additional evidence, same unresolved obligation across revised HEAD and repeated resume, distinct authenticated failure, unsafe identity) when implementing the actual checkpoint reader/writer. The C01 AST and types tests are **not** runtime recovery or dynamic control-flow proof. C08 must add deterministic graph + Git/postcheckpoint/real-Pi certification and exhaustive negative return variants; deep indirect exceptions and external Studio HTTP/queue faults remain behavioral-fixture responsibilities, with outer queue/HTTP self-healing and OS crashes out of scope.

Known future correction-policy gaps are explicit in the matrix: direct terminal author/scope escalation, no-write Event/Interactive-to-adaptive contradictions, essential blocked specialist with independent continuation only, an unknown diagnostic that is advisory-only, competing assessment phases, potential uncaught pretry job reads, and Studio intent inferred from reason prose. **C01 specifies those gaps but intentionally does not implement them.** #197 is not complete when C01 lands; C02–C08 must close them and prove one genuine diagnostic/correction attempt before calling recoverable failures terminal.
